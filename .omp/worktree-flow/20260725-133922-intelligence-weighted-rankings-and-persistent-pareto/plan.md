# Intelligence-Weighted Rankings and Persistent Pareto Labels

## Context

The current comparison score gives every selected metric equal weight, so the checked-in `price intelligence` report does not reach an Artificial Analysis Intelligence Index of 50 until rank 30. Current HEAD `2a6ab1fe042b93b77f060a4b22840ffcfbad31bb` only refreshed generated data; its parent, `f204cf029567ce17d17b98d40c898f493e8a578e`, introduced the decisive label-hiding condition by returning no placement when all eight nearby candidates collide with another label or the 2D trend. In the current 14-model Pareto set, Chromium at 1440px painted only 9 optimal names on each canvas; at 390px it painted 0 on the main canvas and 2 on the Pareto-only canvas. The end state gives Intelligence twice the weight of every other selected comparison metric and gives every on-canvas Pareto-optimal dot a visible name on both canvases through nearby labels or leader-line callouts, minimizing collisions and permitting label overlap only as a terminal impossible-density fallback.

## Approach

### 1. Weight Intelligence twice in comparison rankings

- In `src/llm_comparison/compare_models_core.py`, add the exact scoring policy constant `SCORING_WEIGHTS = {"artificial_analysis_intelligence_index": 2.0}` and keep every unlisted metric at weight `1.0`. Remove the now-unused `statistics` import after replacing `fmean`. Do not add a CLI/URL setting and do not apply this map to the separate OpenCode Go `value_score` pipeline.
- Keep `relative_geometric_score(values: dict[str, float]) -> float` unchanged at its call boundary, but compute `100 * exp(sum(weight(category) * log(ratio(category))) / sum(weight(category)))`, where the existing `metric_reference_value` and `is_lower_better` continue to define each ratio. This preserves fixed references, model-set independence, nonpositive-value exclusion, and a score of 100 at all references; a single selected metric is unaffected because its weight cancels.
- Add `"scoringWeights": SCORING_WEIGHTS` to the comparison payload assembled by `write_html`. In `src/llm_comparison/compare_models_template.py::relativeGeometricScore(graph, categories)`, read `payload.scoringWeights[category] ?? 1`, sum weighted log-ratios, divide by the summed weights, and leave both `scoreSourceRows` and `scoreEmbeddedRows` calling that shared function. This is a clean cutover: do not duplicate a second browser-only coefficient or alter `opencode_go_payload`.
- Update the user-visible scoring explanation in the template About panel and the formula description in `README.md` to state that Artificial Analysis Intelligence counts twice while every other selected metric counts once. Regenerate `public/index.html` from the canonical template with the current category order; never patch generated HTML independently.

### 2. Guarantee optimal labels with shared callout layout

- In `src/llm_comparison/compare_models_template.py`, retain `placedContainedLabel` and the existing rectangle/segment geometry, but split model-label layout from drawing. Add `function drawProjectedPoint(ctx, point)`, `function layoutModelLabels(ctx, labelPoints, bounds, options = {})`, and `function drawModelLabels(ctx, layout)`. Each input point is exactly `{ row, x, y, radius, fillStyle, alpha }`; the only option is `{ avoidSegments = [] }`. The layout result is `{ placements, hidden }`; each placement is `{ point, text, x, y, bounds, font, fontSize, textAlign, maxWidth, leader }`, with `leader` either `null` or `{ start, end }`. `draw2D(categories, config)` and `draw3D(categories, config)` must use `drawProjectedPoint` for their initial marker pass and the same layout/draw helpers for labels; `drawParetoGraph` already routes its optimal-only rows through those shared renderers, so do not create a second Pareto-only algorithm or a DOM overlay.
- Build the whole layout before painting. Process optimal names independently of Final Score: precompute their valid nearby candidates, then order names by candidate count ascending, measured text width descending, and model name ascending. At `font = "700 12px sans-serif"`, examine the existing eight candidates by the exact tuple `(labelOverlapCount, markerIntersectionCount, avoidOrLeaderIntersectionCount, displacement, candidateIndex)`; require `labelOverlapCount === 0`, reserve `expandedRect(bounds, 4)` for the required pairwise gap, and collect an optimal name instead of returning `null` when no nearby candidate remains.
- For each collected optimal name, generate left- and right-lane candidates inside the existing label bounds. Reuse `labelBoundsFor` and the existing contained `maxWidth`; set lane anchors to `bounds.left + 3` with `textAlign = "left"` and `bounds.right - 3` with `textAlign = "right"`. Candidate baselines start at `bounds.top + 3 + actualBoundingBoxAscent`, advance top-to-bottom at 16px, and stop before `bounds.bottom - 3 - actualBoundingBoxDescent`. Choose the minimum exact tuple `(labelOverlapCount, markerIntersectionCount, avoidOrLeaderIntersectionCount, abs(labelCenterY - point.y), leaderLength, sideIndex, baseline)`, where `sideIndex` is 0 for left and 1 for right; require zero label overlaps, reserve the label rectangle expanded by 4px plus the leader segment, and connect the point circumference to the nearest point on the label rectangle.
- If any optimal name remains unplaced at 12px, discard that tentative layout and retry every optimal name uniformly at `font = "700 10px sans-serif"` with the same ascent/descent bounds and 14px baseline intervals; never vary size by model and never truncate the model string (continue passing the full string plus the contained `maxWidth` to `fillText`). Always append two terminal lane candidates at the left/right anchors with the baseline clamped as close as possible to the point's `y`; if the ascent/descent-safe interval is empty, use the vertical midpoint, ensuring the candidate list itself is never empty. If the 10px retry still exhausts collision-free slots, choose the minimum lane tuple above without requiring `labelOverlapCount === 0`. Every visible optimal point therefore receives text; overlap or slight bound overflow is the pathological last fallback, not omission.
- `drawModelLabels` draws callout leaders first as solid 1px strokes in `--chart-optimal-label` at `0.55` alpha, calls `drawProjectedPoint` for each placement point so markers sit above leaders, then restores each placement's `font`, `textAlign`, `maxWidth`, halo, and text. This distinguishes callouts from the existing 3px dashed trend and keeps dots and names legible in both themes and PNG exports. A nearby label has `leader = null`.
- After optimal placements are reserved, place suboptimal names at `font = "700 12px sans-serif"` with the same nearby tuple and `labelOverlapCount === 0`; suboptimal names may enter `hidden` when no clean slot exists, and non-Pareto points remain dot-and-tooltip only. In 3D, exclude projected points outside the canvas by more than their marker radius from static label layout: the visibility guarantee applies to dots currently inside the viewport, while a rotated-offscreen dot and name re-enter together. Recompute from projected positions on every existing resize, 2D pan/zoom, 3D rotation, fullscreen, theme, and export render.
