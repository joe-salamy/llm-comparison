# OpenCode Go Value Comparison

## Context
Add a dedicated OpenCode Go value section to the existing GitHub Pages site, selected with `?view=opencode-go`, while preserving the current general LLM comparison as the default view. Scrape the authoritative pricing and monthly Usage table from `https://opencode.ai/docs/go/`, join each Go model to the existing Artificial Analysis Intelligence Index, calculate Artificial Analysis’s 7:2:1 cached-read/input/output blended price, and rank models by intelligence points per blended-price dollar. The Go Usage allowance is displayed but never changes the value score; models without an Intelligence Index remain visible and unranked.

## Approach
### 1. Add a source-specific OpenCode Go data pipeline
- Create `src/llm_comparison/update_opencode_go.py`, following the pure-snapshot/parser plus async Playwright orchestration split in `src/llm_comparison/update_artificial_analysis.py`; no existing source-specific parser can identify the OpenCode page’s third table, so keep this logic separate from Artificial Analysis’s `extract_table`.
- Define repository-root defaults exactly as `DEFAULT_URL = "https://opencode.ai/docs/go/"`, `DEFAULT_CSV = PROJECT_ROOT / "data/opencode_go.csv"`, `DEFAULT_AA_CSV = PROJECT_ROOT / "data/results.csv"`, and `DEFAULT_PUBLISH_SCRIPT = PROJECT_ROOT / "scripts/update-gh-pages.py"`. Add the console entry point `update-opencode-go = "llm_comparison.update_opencode_go:main"` in `pyproject.toml`; retain the existing `playwright>=1.49` `update` extra. Import and reuse `run_publish_script` from `update_artificial_analysis.py` instead of introducing a second subprocess implementation, preserving the existing package/direct-script import convention.
- In `scrape_table(url: str, *, timeout_ms: int, headed: bool) -> tuple[list[str], list[list[str]]]`, launch Playwright Chromium as the existing updater does, navigate to the URL, and select the unique table whose normalized headers equal `Model`, `Input`, `Output`, `Cached Read`, `Cached Write`, `Usage`. Reject zero matches, multiple matches, empty bodies, and row/header width mismatches with source-specific `RuntimeError` messages rather than accepting a different page table. Return a browser-independent snapshot to pure parsing code and always close the browser in `finally`.
- Parse `$` values as finite non-negative decimals in USD per 1M tokens, parse `-` as a blank cached-write value only, and require Model, Input, Output, Cached Read, and Usage on every source row. Reject duplicate source labels except the two explicitly tiered Qwen Plus labels. Preserve the source label for diagnostics.
- Collapse the 18 scraped price rows into one deterministic row per canonical Go model. For `Qwen3.7 Plus` and `Qwen3.6 Plus`, store the `≤ 256K tokens` prices as primary fields and the `> 256K tokens` prices as secondary `long_context_*` fields with `long_context_threshold_tokens = 256000`; require both tiers and identical Usage values. Every other label maps one-to-one. Write `data/opencode_go.csv` in the source’s stable model order with exact columns: `model,input_price_usd_per_1m_tokens,output_price_usd_per_1m_tokens,cache_read_usd_per_1m_tokens,cache_write_usd_per_1m_tokens,monthly_usage_usd,long_context_threshold_tokens,long_context_input_price_usd_per_1m_tokens,long_context_output_price_usd_per_1m_tokens,long_context_cache_read_usd_per_1m_tokens,long_context_cache_write_usd_per_1m_tokens,artificial_analysis_model,artificial_analysis_intelligence_index,opencode_go_blended_usd_per_1m_tokens,long_context_blended_usd_per_1m_tokens,value_score`.

### 2. Join the current Artificial Analysis Intelligence Index and calculate value
- Add pure functions in `update_opencode_go.py` for reading `data/results.csv`, selecting Intelligence Index candidates, calculating costs, and producing output rows. Require the AA headers `model` and `artificial_analysis_intelligence_index`; a missing header fails the update before writing output.
- Use an explicit `AA_MODEL_ALIASES: dict[str, tuple[str, ...]]` rather than fuzzy substring matching. Allow these candidate display names: `Grok 4.5` → `Grok 4.5 (high)`; `GLM-5.2` → `GLM-5.2 (max)`, `GLM-5.2`; `GLM-5.1` → both exact `GLM-5.1` rows; `Kimi K3` → `Kimi K3`; `Kimi K2.7 Code` → `Kimi K2.7 Code`; `Kimi K2.6` → both exact `Kimi K2.6` rows; `MiMo V2.5` → `MiMo-V2.5`; `MiMo V2.5 Pro` → both exact `MiMo-V2.5-Pro` rows; `MiniMax M3` → `MiniMax-M3`; `MiniMax M2.7` → `MiniMax-M2.7`; `MiniMax M2.5` → no current candidate; `Qwen3.7 Max` → `Qwen3.7 Max`; `Qwen3.7 Plus` → `Qwen3.7 Plus`; `Qwen3.6 Plus` → `Qwen3.6 Plus`; `DeepSeek V4 Pro` → `DeepSeek V4 Pro (max)`, `DeepSeek V4 Pro (high)`, `DeepSeek V4 Pro`; `DeepSeek V4 Flash` → `DeepSeek V4 Flash (max)`, `DeepSeek V4 Flash (high)`, `DeepSeek V4 Flash`.
- Parse Intelligence Index cells by accepting a finite numeric value with an optional trailing `*`. From the allowlisted candidates choose the highest numeric index, preserve that AA row’s full display name in `artificial_analysis_model`, and resolve an equal-score tie by alias tuple order then CSV order. Do not let similarly prefixed models cross-match, especially MiMo Pro/base. If an allowlisted model has no numeric candidate, leave its AA model, index, and value blank; this is the required behavior for MiniMax M2.5 and keeps it visible but unranked.
- Calculate `opencode_go_blended_usd_per_1m_tokens = (7 * cache_read + 2 * input + output) / 10` and the long-context equivalent from the secondary Qwen fields. Cached-write price is collected and displayed but excluded because Artificial Analysis’s published blend is 7 cached-read : 2 uncached-input : 1 output. Calculate `value_score = artificial_analysis_intelligence_index / opencode_go_blended_usd_per_1m_tokens`; reject a zero or non-finite blended price instead of emitting infinity. Usage is not an input to either formula.
- Keep full numeric precision in CSV sort values and round only for display. Pin the current source examples: Kimi K3 blends to `2.31`; DeepSeek V4 Flash blends to `0.05796` and, with the selected highest current index `40`, scores approximately `690.131`; Qwen3.7 Plus blends to `0.268` at ≤256K and `0.804` above 256K.
- Expose CLI options matching the established updater where applicable: `--url`, `--csv`, `--aa-csv`, `--headed`, `--timeout-ms`, `--skip-publish`, and `--publish-script`. `async_main` must complete scrape, validation, join, and calculation before calling the deterministic CSV writer, then optionally call the existing `run_publish_script` behavior. Any scrape/join/validation failure occurs before opening the output path and therefore leaves the prior generated CSV untouched.

### 3. Embed and render a dedicated view in the existing report
- Change the exported writer signature to `write_html(output_path: Path, rows: list[dict[str, Any]], columns: list[Column], categories: list[str], pareto: list[ParetoFlag], available_categories: list[str] | None = None, opencode_go_rows: list[dict[str, str]] | None = None) -> None`. Add `--opencode-go-input` to `compare_models.parse_args()` with `Path("data/opencode_go.csv")` as its default; `compare_models.main()` is the only production caller and must load that CSV with the existing `read_rows()` before calling `write_html`. The 14 direct calls in `tests/test_compare_models.py` retain the `None` default unless a test is exercising the Go payload; no other `src/` or `tests/` callsite exists. If the configured Go CSV is missing, fail the CLI with its path instead of silently generating production HTML without the requested section. Do not add a second HTML page or a compatibility wrapper.
- Serialize the dedicated model under the exact JSON key `payload.openCodeGo` with keys `columns`, `rows`, `categories`, `graphCategories`, `sourceUrl`, and `formula`, retaining the existing top-level comparison payload. Use the existing `Column`, `json_ready_rows`, Pareto helpers, `json.dumps(...).replace("</", "<\\/")`, and sole `__PAYLOAD__` replacement: while serializing, copy each ranked row’s `value_score` into the internal `final_score` field consumed by `json_ready_rows` so `row.score` drives color scaling, but expose the sortable table cell only as `value_score`; use `None` for the unranked row’s internal score. Compute Pareto flags on rows having both graph values and map those flags back to their original row positions, assigning the existing all-false default to MiniMax M2.5. The table columns are Model, Artificial Analysis Intelligence Index, Input, Output, Cached Read, Cached Write, Blended Price, >256K Blended Price, Usage, and Value Score; blank long-context cells apply to non-tiered models, and blank index/value cells apply to unranked models. The only graph categories are Intelligence Index (higher is better) and OpenCode Go blended price (lower is better); Usage, cached write, long-context price, and Value Score are never graph categories.
- Extend `format_value` with OpenCode-specific branches before the generic USD branch: primary and long-context prices render as dollars with up to six decimal places and trailing zeroes removed; Usage renders as whole dollars when integral; Intelligence Index renders as its numeric source value without the optional AA `*`; and Value Score renders to two decimals. Keep the underlying `cells.sort` values unrounded. Label the score `Intelligence per blended $/1M tokens`, set `sourceUrl` to `https://opencode.ai/docs/go/`, set `formula` to `(7 × cached read + 2 × input + output) ÷ 10`, and display both beside the Go results so “best value” is auditable.
- Add semantic header navigation with links for `Comparison` and `OpenCode Go value`. Parse only the exact query value `view=opencode-go`; absent or unknown values select Comparison. Mark the active link with `aria-current="page"`, preserve theme behavior, and confine the existing `metrics`/`excludeZeroPrice` URL options to Comparison.
- Reuse the single chart/table shell and existing `renderTable()`, sorting, 2D scatter/Pareto, tooltip, theme, zoom, and responsive behavior. In Go mode hide `.controls-wrap`, replace the H1/summary/about content with source-specific copy and links to OpenCode Go and Artificial Analysis, activate `payload.openCodeGo`, default sort descending by `value_score`, and render without calling `applySelection()`, `scoreEmbeddedRows()`, `scoreSourceRows()`, or percentile scoring. Update `updateScoreScale()` to filter for finite numeric `row.score` values, and update `renderTable()` to apply score background/text colors only when `row.score` is finite; this leaves unranked rows neutral instead of coercing `null` to zero. This preserves the requested direct intelligence-per-dollar metric rather than the general page’s average percentile score.
- Gate CSV loading by view: Comparison fetches `data/results.csv`/`../data/results.csv` and retains its current initialization; Go fetches `data/opencode_go.csv`/`../data/opencode_go.csv`, validates its required headers, creates the dedicated cells/graph rows without recomputing value, and falls back to the embedded `payload.openCodeGo` on fetch failure. MiniMax M2.5 remains in the table with `Unranked` for Intelligence/Value and is excluded from plotted points and score-color scaling. Primary Qwen price/value controls ranking; show the >256K blend only as secondary table information.

### 4. Include the generated data in the existing Pages deployment
- Add `data/opencode_go.csv` to `GENERATED_FILES` and `PublicFile("data/opencode_go.csv", "data/opencode_go.csv")` to `PUBLIC_FILES` in `scripts/update-gh-pages.py`; keep `public/index.html -> index.html` as the sole HTML document. This is required because the publisher reconstructs `gh-pages` exclusively from `PUBLIC_FILES` and rejects dirty generated paths outside `GENERATED_FILES`.
- Regenerate `public/index.html` through the normal `compare-models` flow after the new CSV exists so the committed fallback payload and view bootstrap match the template. Do not hand-edit the generated file. Ensure both `update-artificial-analysis` and `update-opencode-go` can publish only when all required public artifacts exist; neither command invokes the other or publishes an intermediate two-source refresh.
