# Open Code Go Value Chart and Nonlinear Value Metric

## Context
The Open Code Go value page currently plots intelligence against cost with the requested axes reversed and ranks value as artificial-intelligence points per dollar. Change the main chart to place cost on the X axis and intelligence on the Y axis, then replace the linear ratio with a value metric that does not systematically reward cheap low-intelligence models.

## Approach
1. Add a pure `cost_adjusted_intelligence(intelligence: Decimal, blended_price: Decimal) -> Decimal` helper in `src/llm_comparison/update_opencode_go.py`; no equivalent metric helper exists in the repository. Compute the selected balanced score exactly as `intelligence - Decimal(10) * blended_price.log10()`, where `blended_price` is the numeric OpenCode Go 7:2:1 price in USD per 1M tokens, so the fixed reference price is `$1/1M tokens`. This score is the base-10 logarithm of an underlying value proportional to `10 ** (intelligence / 10) / blended_price`: intelligence utility is exponential, while a 10-point Intelligence gain exactly offsets a 10× price increase.
   - Keep the CSV/storage key `value_score`, descending sort, score coloring, Pareto coordinates, two-decimal display, and use of the primary (not >256K) blended price. The key is already generic; renaming it would add a schema migration without clarifying the UI.
   - In `enrich_rows`, replace `intelligence / primary_blend` with the helper. Preserve full `Decimal` precision and `decimal_text`; presentation remains the only rounding point.
   - Preserve the existing missing-Intelligence path: leave Intelligence and `value_score` blank, display `Unranked`, and omit the row from plotting, Pareto classification, score coloring, and ranked sorting. Reject non-finite or negative Intelligence with the exact error `OpenCode Go intelligence must be finite and non-negative`; zero Intelligence is valid and produces only the logarithmic price adjustment. Preserve `blended_price` rejection of zero, negative, and non-finite cost, because logarithmic cost requires a strictly positive argument and all current ranked costs are positive.

2. Reverse the OpenCode Go chart axes in `compare_models_core.opencode_go_payload` by changing both ordered contracts to cost first and intelligence second:
   - `graph_categories = [OPENCODE_GO_BLEND, OPENCODE_GO_INTELLIGENCE]`.
   - Emit `categories` in the same order, retaining the exact existing descriptors `OpenCode Go blended price ($/1M tokens)` with `lowerIsBetter: True` and `Artificial Analysis Intelligence Index` with `lowerIsBetter: False`.
   - Do not add an OpenCode-specific renderer branch. `draw2D` in `src/llm_comparison/compare_models_template.py` already maps `categories[0]` to the horizontal accessor/domain/label and `categories[1]` to the vertical accessor/domain/label; the Comparison payload already uses the required cost-then-intelligence pattern. Category reordering leaves Pareto membership unchanged because dominance is independent of dimension order.

3. Replace every user-visible linear-ratio description while retaining the established Go bootstrap:
   - Change the `value_score` column label in `OPENCODE_GO_COLUMNS` to the exact text `Cost-adjusted intelligence`.
   - In the OpenCode Go About list in `src/llm_comparison/compare_models_template.py`, replace the old points-per-dollar bullet with `Cost-adjusted intelligence = Intelligence − 10 × log₁₀(blended price ÷ $1 per 1M tokens).` and add `A 10-point Intelligence gain offsets a 10× higher blended price.` Keep the separate 7:2:1 blended-price formula and the Usage/cached-write exclusion disclosure.
   - Change the Go summary suffix from `ranked by Intelligence per blended $/1M tokens` to `ranked by cost-adjusted intelligence`, and the Go tooltip score label from `Value Score` to `Cost-adjusted intelligence`. The tooltip’s category loop will naturally list cost before Intelligence after step 2. Keep `goValueKey = "value_score"`, live-CSV parsing, embedded fallback, descending default sort, and adaptive score colors unchanged.

4. Update the behavior-defining tests before regenerating artifacts:
   - In `tests/test_update_opencode_go.py`, replace the old DeepSeek V4 Flash ratio assertion with the logarithmic result (`40 - 10 × log10(0.05796) ≈ 52.3687162320`). Add helper contracts `(50, 1) -> 50`, `(50, 10) -> 40`, `(50, 0.1) -> 60`, and `score(50, 1) == score(60, 10)`; cover zero Intelligence; reject negative/non-finite Intelligence; and retain existing zero/non-finite blended-price rejection, missing-AA, 7:2:1 blend, and Usage-invariance coverage. Add the observable anti-bias assertion that current Kimi K3 `(57, 2.31)` scores above MiMo V2.5 `(37, 0.05796)`.
   - In `tests/test_compare_models.py::test_write_html_embeds_dedicated_opencode_go_payload`, update the fixture score and display/label assertions, assert exact category and `graphCategories` order `[OPENCODE_GO_BLEND, OPENCODE_GO_INTELLIGENCE]`, and retain unrounded sort values and Unranked behavior. Update the navigation/bootstrap content assertions for the exact formula, tradeoff sentence, summary wording, and tooltip label.

5. Regenerate rather than hand-edit derived files. From the repository root, run `python -m llm_comparison.update_opencode_go` to recompute `data/opencode_go.csv` with the new score from current OpenCode Go pricing and checked-in Artificial Analysis data, then run `python -m llm_comparison.compare_models price intelligence --opencode-go-input data/opencode_go.csv --output public/index.html` so the published single-page report embeds the new data, labels, formula copy, and axis order.

## Assumptions & contingencies
- The selected balanced calibration is fixed at 10 Intelligence points per 10× price. The `$1/1M tokens` reference makes a model at that price retain its raw Intelligence as its displayed adjusted score; changing the reference would add the same constant to every model and would not change ranking.
- Keep the chart’s established linear cost axis. If the post-swap browser smoke shows cheap points visually compressed, do not introduce a log axis in this change: the request is axis placement plus metric correction, and the score already applies logarithmic cost treatment.
- The live updater requires the project’s `update` dependencies, Playwright Chromium, network access to `https://opencode.ai/docs/go/`, and the checked-in Artificial Analysis CSV. If live scraping is unavailable, preserve every existing CSV field and row: use `csv.DictReader` plus the new `cost_adjusted_intelligence` helper to recompute only nonblank `value_score` cells from each row’s existing `artificial_analysis_intelligence_index` and `opencode_go_blended_usd_per_1m_tokens`, leave blank scores blank, write with the original header order through a temporary file, and atomically replace `data/opencode_go.csv`; do not change `scraped_at`. The live updater may return changed model rows or prices; when it succeeds, do not pin regenerated rank order to the 2026-07-17 snapshot—use the synthetic/existing test fixtures for exact ranking contracts, require every regenerated ranked score to satisfy the formula, and preserve strict source-table validation.
